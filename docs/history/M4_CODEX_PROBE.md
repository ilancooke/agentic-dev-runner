## Fixed scope and settings

- A new live `DisposableRoot`, generated committed Python fixture from
  `tests.support.projects.make_project`, and a separate test-role StateBoundary.
  No runner checkout, reference repository or operational state is a job fixture.
- Runner-owned immutable M4 image, recorded binary SHA-256 and CLI 0.166.0. Exact
  image/binary IDs must be included in the eventual authorization request.
- Model `gpt-6.1-sol`; `model_reasoning_effort="high"`; no speed tier/paid fallback,
  model substitution, lower effort, automatic downgrade response or web search.
- At most two turns: a fresh session and one resume by its exact recorded UUID;
  at most five minutes total, with no automatic retry. Use existing subscription
  usage only if its supported isolated auth path is verified. API billing or
  credential changes require separate authorization and are outside this plan.
- Same mounts/UID/resources as the passing offline boundary tests. Retain Docker
  seccomp, AppArmor, no-new-privileges and dropped capabilities, plus Codex's named
  restricted filesystem/network profile. No Docker socket inside the container.
- Publication, real GitHub/cloud integrations, production connections, services,
  deployment and spending beyond the expressly approved Codex usage are excluded.

The exact fresh/resume argv prefixes are generated by
`agentic_runner.codex.command()` / `command(resume_id=<recorded UUID>)`. They use
the same `settings()` prefix and `--ignore-user-config --ignore-rules
--strict-config --json --skip-git-repo-check --model gpt-6.1-sol -`. Prompts enter
bounded stdin, never shell interpolation. The implemented final-report schema is
`REPORT_SCHEMA` in that module. The future live adapter must pass it via the
installed supported output-schema mechanism and retain the session privately.

## Required offline prerequisites

Run the reviewed container suite against the exact candidate image. Its Codex and
Chromium sandbox capability tests must stop skipping. A sandbox sentinel must
execute under the actual configured profile. Do not fix namespace denial using
privileged containers, extra host mounts, disabled seccomp/AppArmor, legacy weaker
sandboxing, or Chromium's no-sandbox switch. A different compatible environment
requires review and repeat boundary tests, including its new image/configuration.

Implement and review a narrow credential-isolated transport. It must allow only
the necessary provider model traffic and deny project commands access to upstream
tokens, Codex auth/session stores, token refresh responses, proxy endpoints and
parent process descriptors. Dependencies/build/tests get no transport at all.

Network destinations outside the fixed provider path must remain denied, including
metadata, RFC1918, host gateways, homelab, production and arbitrary public hosts.
Tokens must never enter checkout files, shell environment, image layers, public
logs or agent-readable mounts. An unrestricted HTTP CONNECT proxy is not acceptable.

Then produce a concrete executable fresh/resume probe, including transport and
exact auth exposure, for review against the standing testing authorization. Ask
only if the action needs authority outside that scope. This document is not evidence
that the transport or real permission behavior already works.

## Sources used for representation and policy design

The fetched official [GPT-6.1 Sol model page](https://developers.openai.com/api/docs/models/gpt-6.1-sol)
documents the model ID and high effort support. The installed bundled catalog was
also checked inside the container. Neither establishes account access.

filesystem/network controls and Linux bubblewrap requirements. The local namespace
failure was observed independently; no fallback is authorized by that documentation.
The [app-server reference](https://learn.chatgpt.com/docs/app-server) was evaluated
because it exposes explicit start/resume/turn permission fields. It cannot solve
missing OS sandbox capabilities; no app-server transport was enabled here.
