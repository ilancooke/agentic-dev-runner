Reproduce the read-only preservation comparison from the runner root (this is an
operator check, not a test fixture that enrolls the reference repository):

```bash
python3 - <<'PY'
import hashlib
import json
from pathlib import Path
root = Path.cwd()
manifest = json.loads((root / 'docs/evidence/m1-preservation.json').read_text())
for group, base in [('prototype', root), ('reference', Path(manifest['reference_root']))]:
    expected = manifest[group]
    for relative, digest in expected.items():
        path = base / relative
        assert path.is_file(), f'Missing: {path}'
        assert hashlib.sha256(path.read_bytes()).hexdigest() == digest, f'Changed: {path}'
    if group == 'reference':
        actual = {str(p.relative_to(base)) for p in base.rglob('*') if p.is_file() and not any(part in manifest['reference_exclusions'] for part in p.relative_to(base).parts)}
        assert actual == set(expected), 'Reference file inventory changed'
    print(f'{group}: {len(expected)} files unchanged')
PY
```

## Limitations and remaining risks

The guard constrains trusted fixture helpers, not arbitrary or hostile Python code.
Concurrent malicious path replacement/check-use races are not solved by this test
harness. Container enforcement is deferred to M4; no project code, Docker, Codex,
GitHub, AWS, service, reboot or production checks ran. Model/effort identifiers are
not yet capability-tested. No execution or publication safety is claimed.

Operational state was neither read nor used; no operational environment was a
fixture. Reference caches/venv are outside the manifest's comparison scope. A wheel
release installation and other Python/OS versions were not tested; the editable
development setup requested by M1 was tested. Build setup needs setuptools >=68
from an available package index/wheel source. Future tests must continue using the
guarded helpers and explicit `tests/` discovery.
