## Limits and next work

The supported grammar/evidence rules are explicit in [DISCOVERY.md](../DISCOVERY.md).
The initial global policy selects Python 3.12.0/Node 22.0.0 baselines and npm only;
unsupported constraints/managers and mixed projects diagnose instead of guessing.
No runtime image was built or capability-tested. Patch requirements and actual
runtime capabilities must be checked when M4 provisions execution.

Instruction conflicts are mechanically checked for documented Runtime/Verification
declarations. Free-form instruction prose is inventoried/hashed for review, not
semantically proven consistent; it cannot override deterministic selectors.
External links are not fetched or captured as approved requirements. CI YAML is
inventory only. These limits are emitted/documented; discovery success is neither
authorization nor verification success.

Results read the current worktree and cached refs, without an atomic committed
snapshot, locks, remote freshness guarantees or a hostile-filesystem boundary.
M3 must define approval coverage, protect scope, record committed requirements and
implement durable state/canonical locking. M4/M5 must enforce execution/publication
boundaries. No existing prototype/operational state is imported. The runner's own
unborn development checkout is not a valid full preflight fixture; tests generated
separate repositories with real local commits and cached remote-default refs.
