# Native M4 disposable probe — reviewable scope

User authorization: the accepted [dedicated VM decision](TRUSTED_VM_DECISION.md)
and standing permission for required M4 tests cover these probes. No repeated
authorization is needed for the same bounded test.

`python -m tests.support.probe_native_m4` creates a new live owned DisposableRoot,
generated committed fixture and separate test-role state. It checks pinned Codex
0.166.0 capabilities and executes a real native VM-user command with a
fake private HOME. There is no account access or inference in this default mode.

`--real-codex` uses the existing development user's HOME/CODEX_HOME normally,
without copying tokens, creating an API key, changing credentials or enabling
plugins/services. Codex may create its ordinary session history in that home.
Exactly one fresh prompt and one exact-ID resume use `gpt-6.1-sol` and high effort;
each process is limited to 180 seconds and 4 MiB captured output. No retries,
smaller models, lower effort, paid API fallback, GitHub mutation or publication.
The source contains both complete prompts for review.

Both prompts instruct Codex to execute the fixed generated Python probe once.
That script writes inside the generated checkout, writes to a second owned fixture directory outside the checkout, and verifies that a fake development-auth file is deliberately readable
under the accepted trust model. It prints only a success marker. The trusted driver
checks the resulting files, expected VM-user write, same session UUID, token usage,
pending-operation resolution and unchanged implementing phase. Agent prose alone
cannot pass this test. No root process is used. Fresh and resumed launches explicitly use
`--dangerously-bypass-approvals-and-sandbox`, as the user requested. There is no
additional Codex sandbox or permission-profile probe.

`--docker` additionally builds/runs/tests a tiny generated Python Docker application
through the host daemon, then checks its unique image label and removes only that
generated tag. It mounts no host socket into the application container. It uses
the cached pinned Python base and offline image build/run. No shared image prune,
production service, external repository or operational state is a fixture.

The capability check pins binary SHA-256
`b8a11fedf24b2dfb59a70c9e52b030f9a508dcd49cd2dd0d41956f4c785156b8`.
Native permission settings and fresh/resume argv are generated by `native_codex.py`.
Failures retain pending intent/partial work in the fixture during inspection; the
test lifecycle eventually deletes its generated root. Normal Codex session history
is retained under the development account. Public output contains metadata only.

## Recorded outcome

The real fresh/resume plus Docker command passed in M4. Both recorded turn contexts
confirm `gpt-6.1-sol`, high effort, approval never and danger-full-access. See
[acceptance evidence](evidence/M4-NATIVE.md) and [safe session metadata](evidence/m4-native-real-check.json).
Default account-free probes remain the routine check; repeat real usage only when
new changes or unresolved concerns justify it.
